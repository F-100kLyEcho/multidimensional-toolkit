# 获取路径页设计思想

## 定位

获取用户指定路径下的文件名列表与合并文本内容，供后续处理使用。

## 核心设计：两级规则

规则是页面的大脑，分两级、各司其职：

- **全局规则**：所有项目共享的初次筛查规则，在扫描阶段物理过滤。
- **项目规则**：仅当前项目生效，决定节点的展示状态（正常/已排除/已豁免/占位）。

设计思路：把「跨项目通用」的规则抽出来，避免每个项目重复配置；把「项目特有」的规则留在项目内，保持灵活。语法类似 `.gitignore`，每行一条，支持 `#` 注释，降低学习成本。

## 七类规则语义

| 类别 | 含义 | 语法示例 |
|------|------|---------|
| 精确文件夹 | 排除指定路径文件夹 | `node_modules/` |
| 递归文件夹 | 递归排除同名文件夹 | `**dist/` |
| 精确文件 | 排除指定路径文件 | `src/secret.ts` |
| 递归文件 | 递归排除同名文件 | `**.log` |
| 豁免 | 重新包含被排除项 | `!src/important.ts` |
| 通配符 | glob 模式匹配排除 | `*.log` |
| 占位文件夹 | 文件夹保留但子内容不扫描 | `@old_components` |

冲突解决：后添加的规则（索引更大）胜出；占位文件夹优先级最高，其子项不可豁免。支持手动输入和右键菜单添加规则。

## 扫描设计

输入路径后渐进式扫描（广度优先、支持暂停/继续）。核心目的不是"快"，而是避免一次性扫描阻塞进程导致界面冻结——用「渐进」换取「不卡死」。扫描结果按批次渲染，保持界面响应。

## 合并设计

将未排除文件的内容合并为单个输出文件，每段含路径注释和分隔行。合并规则文件（`.mergelist`）管理参与合并的文件列表，支持多套规则切换；合并配置（支持的文件类型、输出格式、注释/分隔开关）跨项目生效。支持一键收集未排除节点自动合并。

## 输出位置

扫描输出与合并输出均固定在工作空间内，产物集中、位置可预测，仅格式（txt/md）可切换。

## 交互

三栏布局：左栏（路径输入 + 文件树）、中栏（规则编辑）、右栏（预览：树形/纯文本/扁平）。
快捷键 Q/W/E：切换中栏、切换右栏、重置布局。
右键菜单可添加各类规则与批量排除。
